# RuleCourt M0 — Root Move Court 正式设计文档

**版本：** 1.1

**状态：** 设计决策已确认，实施与来源核验尚未完成

**设计基线：** PRD v0.5、Technical Specification v0.5、已确认的 16 项评审决策、领域词汇表、局部移动裁决 ADR 与 M0 评测协议

**目标：** 完成可追溯的局部移动裁决系统，并检验动态 Agent 相对于强固定工作流的增量价值。

## 问题陈述

复杂桌游玩家描述具体局面后，需要知道拟议行动在什么条件下合法、依据哪些规则，以及还缺哪些事实。单纯找到规则段落不能解决多个规则组合、阵营例外、局面计算、自然语言缺省和事实更正等问题。

错误的确定回答比明确说明范围或追问更容易误导玩家。系统必须防止把未提及的棋子视为零、把旧局面的计算用于新局面，以及把“执行过检索和模拟”误当成“结论已被验证”。

M0 同时承担一个实验目标：即使整套系统优于普通 RAG，也不能直接证明动态 Agent 有价值。需要与共享抽取器、规则库、领域引擎和门禁的固定工作流比较，区分确定性计算的贡献与动态调查的贡献。

## 方案

用户用自然语言建立一个 Case。系统接纳有来源且无歧义的事实，确认裁决范围，只追问可能改变结论的信息，调查固定版本规则，并通过确定性领域计算和证据验证生成本轮结果。

M0 提供的是**局部移动裁决**：检查明确列入范围的 Marquise / Eyrie warrior Move 和 Eyrie Decree Move 条件。LEGAL 不承诺完整回合中的行动机会、全部 Decree 执行进度或所有其他效果都已验证。

| 本轮结果 | 用户可依赖的含义 |
| --- | --- |
| LEGAL | 当前已接纳事实足以证明拟议行动满足声明范围内的条件 |
| ILLEGAL | 当前已接纳事实足以证明拟议行动违反声明范围内的条件 |
| INSUFFICIENT_INFORMATION | 仍有可能改变结论的事实缺口或歧义；返回具体问题并允许继续 |
| UNRESOLVED | 能力范围、证据冲突、证据不可用或运行故障阻止可靠裁决；说明原因并结束本次运行 |

结果展示实际使用的状态、裁决范围、前提、证据、派生事实及验证结果。调查轨迹来自公开操作事件，不展示模型隐藏推理。M0 不显示未经校准的置信度分数。

## 实施决策

### 1. 系统职责与模块边界

- Python 作为实现语言；nanobot 提供 provider、会话、工具调用循环和使用量统计等通用运行能力。实施前固定 commit 并验证实际扩展接口，不把设计中的接口描述当成既有代码事实。
- RuleCourtController 管理 Case 调查进度、预算、结果生成和最终门禁；领域逻辑作为独立能力接入，避免散布修改通用 runtime。
- CaseStore 保存已接纳状态、候选事实、修订、运行记录、验证和历史裁决。
- RuleStore 保存固定版本来源、规则原文、人工确认的规则关系和规则覆盖表。
- RootAdapter 封装 schema 验证、可判定性、优先级、统治派生、移动条件及 Decree 条件。
- 评测器、事实应答器与各对照组独立于正式产品裁决路径；隐藏标签不进入被测系统。
- 初始存储可选 SQLite 或 PostgreSQL；关系边表足以表达 M0 规则关系。具体数据库选择属于实施配置，不改变本设计行为契约。

### 2. 支持范围与前提

目标规则集为 Law of Root Oct 2025。正式录入前核对来源、版本、规则编号和适用条件；本文不替代该核验。

支持 Marquise / Eyrie 的局部统治计算、普通 warrior Move、Eyrie Decree Move，以及这些范围内的例外、缺信息处理与证据裁决。每个 Case 首次裁决前形成适用前提确认；明确用户输入可以完成确认，无需机械地再次询问。

相关前提未变时可以复用确认。新阵营、卡牌、地图或效果信息可能改变前提时，先使相关确认失效，再检查适用性。未提及不等于不存在。未建模且影响所问结论的交互返回 UNRESOLVED；前提事实不清楚时提出具体问题。

### 3. 状态、来源与清单完整性

- LLM 只产生 Proposed State 的事实变更提案。Schema 验证、领域验证和冲突处理通过后才接纳为 Confirmed State。
- Confirmed State 可以不完整，不等于用户逐项点击确认。每项裁决依赖的事实保留来源消息及原文。
- 数量零与未知严格区分；数量使用合法的非负整数。无效状态输入先纠正，不把格式或领域数据错误伪装成有效局面的游戏裁决。
- 棋子和相邻清单默认是部分描述；完整清单声明必须有明确覆盖范围和来源。
- 只有完整清单范围内的未列项可推导为零或不存在；单项明确的零值或不相邻事实无需完整清单。
- 完整清单不等于适用前提确认，也不能用来静默丢弃不支持的棋子或效果。

ScopeAssumption 与 CompletenessAssertion 为独立、可追溯的数据对象。二者均有稳定标识、Case、来源证据、创建修订、生命周期状态和替代关系，只有经 Controller 接纳且对当前修订有效的声明参与计算。

ScopeAssumption 保存范围命题、用户确认值及规则/范围策略版本；不存在对象不等于前提成立。适用前提确认是这些对象在当前修订下的验证结果。CompletenessAssertion 保存集合目标、明确覆盖维度、部分或完整声明以及所指清单快照；不存在有效完整声明时维持部分描述。完整性不能替代范围确认，撤回或更正须使依赖的派生事实失效。

### 4. 事实更新与修订

事实变更区分新增断言、明确更正和撤回。未提及字段保持原值；相同事实可追加来源而不产生无意义修订。

明确更正验证后直接接纳，并保留被替代事实。未明确更正的矛盾陈述保留候选和来源，进入澄清；相关旧事实不能继续作为有效依据。撤回使事实恢复未知。

由完整清单推导出的零值或不存在事实保留依赖。撤回某项事实时同时撤销覆盖该事实的完整性结论，避免再次自动补零。

有效状态变化或相关冲突产生新修订，使旧 Decision、验证记录和裁决的当前有效引用失效。历史记录保留。提交原子校验预期修订；并发更正不能沿用旧结果。Controller 管理的修订、确认和裁决字段不能由任意用户事实补丁写入。

### 5. 可判定性与领域计算

StateRequirementResolver 根据确定性规则依赖判断可判定性，返回真正影响当前结论的缺口，而非固定必填表。

在支持范围及前提已确认时，必要条件已被确定违反即可否决；起点或终点统治条件的一侧成立，即满足该 OR 条件。只有剩余未知仍可能改变结果时才追问。不能在尚未排除相关例外前错误地提前判定。

领域接口区分 DerivedFact 与 Decision。DerivedFact 表示已解析、未知或不支持的派生事实；Decision 表示 ALLOW、DENY、UNKNOWN 或 UNSUPPORTED。统治计算、移动条件和 Decree 条件返回结构化原因、证据规则和派生事实，解释层不重新计算游戏事实。

普通移动验证数量、起终点、相邻关系、可移动兵力和统治条件；Decree Move 增加相关阶段、列和花色条件。Bird 适配由 RootAdapter 统一处理。完整行动机会和 Decree 全部执行进度仍在范围外。

### 6. 规则证据与验证

M0 先人工录入约 6–10 条关键规则，不自动解析完整 PDF。正式采用数量以已核验的支持范围为准，不能为维持数量而遗漏必要规则。

来源保存权威性质、定位、修订和校验信息；权威性质不等于通用优先级。覆盖、澄清、例外和依赖关系由人工确认，RootPrecedencePolicy 决定适用关系。

规则覆盖表只表达 verification obligation：义务的适用条件、可接受证据和满足判据。它作为验证器私有输入，不包含查询、工具顺序或下一步建议，也不为任一策略编译调查路线。Controller 按当前状态验证义务，不强制所有事实齐全。

搜索片段不能直接支持正式裁决，相关原文必须被检查。完成一次反证检索不等于验证通过；记录潜在反证、适用性及剩余冲突。无法可靠覆盖的交互返回 UNRESOLVED。规则覆盖表不得包含评测案例答案。两组共用验证器不等于两组能读取覆盖表；门禁拒绝统一为 VERIFICATION_NOT_SATISFIED，不向调查策略返回未满足义务、缺失规则 ID 或查询建议。详细原因保留在隔离审计记录中。双方仍同等读取公开规则关系、Resolver 缺失字段和领域工具结果；这些共享结果不得读取覆盖表来附加调查路线。

### 7. Case 生命周期与裁决门禁

正常调查经历输入、状态检查、规则调查、规则解析、验证、可提交及完成。新证据可触发继续调查；相关缺失事实可使调查暂停并等待补充。

本轮结果与 Case 永久关闭分开。信息不足返回问题后暂停；无法解决结束本次运行。补充、更正或重试可在同一 Case 内开始或恢复调查。

| 输出 | 必须满足的门禁 |
| --- | --- |
| LEGAL | 范围确认有效；当前 Decision 为 ALLOW；必要证据及例外验证完成，无相关未解决冲突 |
| ILLEGAL | 范围确认有效；当前 Decision 为 DENY；证据支持被违反条件，相关反证及冲突检查完成 |
| INSUFFICIENT_INFORMATION | Resolver 确认有影响结论的事实缺口或歧义；保存字段、原因和问题，不强制成功模拟或非空引用 |
| UNRESOLVED | Controller 记录能力、证据或运行障碍；不强制执行无法完成的模拟和检索 |

LLM 不选择最终权威状态。Controller 将有效 ALLOW/DENY 约束为 LEGAL/ILLEGAL；UNKNOWN 仅在用户事实不足时转成信息不足，UNSUPPORTED 转成无法解决。运行故障独立分类。

Decision、验证和裁决绑定 Case、运行、状态修订、规则集及规则覆盖表版本。缺少条件但仍可补救且有预算时继续调查；达到预算或遇到不可恢复故障时由 Controller 结束，不依赖模型主动配合。

### 8. 工具和公开接口

正式裁决工具限于规则搜索、规则原文检查、事实更新、冲突解析、行动模拟和结果提交。规则搜索支持支持证据、反证和澄清意图。

事实更新返回接纳结果、当前修订、可判定性及缺失字段；冲突不得以无条件成功响应掩盖。结果提交接收 Case 和预期修订，从当前受信任记录生成状态和证据，不接收 LLM 自定的权威裁决。

公开 Case 接口支持创建、读取、提交用户消息、查看状态、查看事件和查看裁决。客户端通过 Case 与修订识别有效结果。结果包含裁决状态、范围、前提、未检查事项、实际状态、规则版本、证据、派生事实和验证记录；没有证据时说明原因，不伪造引用。

### 9. UI、公开事件和可观测性

UI 提供 Case、状态、调查和裁决四个视图。用户可以核对抽取事实、补充信息及更正描述，并看到这些操作如何改变裁决。

公开事件覆盖状态接纳、规则检索与检查、事实推导、模拟、冲突验证和裁决提交。轨迹区分执行与验证结果，不将隐藏推理暴露为日志。

M0 不显示 Confidence 等未经校准分数。每次调查记录模型、provider、token、工具调用与失败、迭代、时延、预算停止原因和结果；解释不能增加证据与计算记录未支持的事实。

### 10. 安全与记忆边界

正式裁决禁用通用 shell、任意文件写入及通用 Web 搜索，不执行 LLM 生成的领域代码。工具参数通过 schema 和领域校验。

会话历史可以进入 runtime session；权威规则来自 RuleStore，当前领域事实来自 CaseStore。用户在提示中嵌入的规则或要求跳过验证不具有权威性。未来 House Rules 与官方规则分开管理，不纳入 M0。

### 11. 实验设计

实现五组：LLM-only、Vanilla Vector RAG、Hybrid RAG + Reranker、固定工作流和 RuleCourt。

核心比较为后两组。它们共享抽取器、模型配置、规则库、领域引擎、规则覆盖表和门禁。固定工作流允许检查全部 M0 规则，按确定性依赖追问。实验处理变量 仅为调查策略：Dynamic Agent 由 LLM 在线选择动作与参数；Fixed Workflow 由冻结流程、查询模板及数据驱动分支确定性选择。固定工作流允许条件分支及全量读取，抽取/解释 LLM 不得兼任规划器。两组共享工具可见信息和预算上限，Agent 的规划开销如实计入；策略和响应投影在开发集冻结，不人为削弱对照。

Golden Case 保存事实、标签、证据、可接受追问、规则版本和核验记录。AI 可准备草稿，正式计分前须由熟悉 Root 的人核验；有争议案例隔离并报告。候选示例不能自动视为已核验标准答案。

首次结果和完整调查分别评估。事实应答器依据已标注事实回答明确问题，不自由生成补充信息；无法回答时保持未知。各组享有相同追问上限，预算跨澄清恢复累计。

同一 canonical family 的改写和 mutation 整体划分，隐藏事实与标签不泄漏给被测系统。记录配置版本、重复运行、缓存条件和配对结果，避免将相关样本当成独立证据。

### 12. 成功指标与冻结条件

完整调查的 Correct Ruling Rate 为主指标：原本可裁决集合中正确给出 LEGAL/ILLEGAL 的数量除以该集合大小。错误、超时和拒答都不得分。

同时报告该集合的裁决覆盖率、全体已确定裁决的准确率、真实非法集合中的错误放行率、应拒答集合的正确拒答率，以及证据、抽取、token、工具、追问和系统时延指标。分母为零报告 N/A；系统故障不能冒充正确拒答。

首次视角依据初始可用事实评分，完整调查视角依据预先允许补充的事实评分；可判定性不取决于系统是否问到了事实。首次另报四状态匹配，完整调查用于主质量结论。

开发集试跑后、保留测试前冻结资源预算、追问上限、重复次数、统计方法、最小增益阈值和错误放行不增加的判定标准。数值未填写前不宣称正式实验就绪。

质量优先；质量相当但成本或时间改善时只报告效率增益。没有达到预设标准时报告“M0 尚未证明 Agent 增量价值”。实验完成与假设成立分开验收。

## 测试决策

### 测试边界与现有基础

仓库目前只有设计及评测资料，没有应用实现或可复用的测试套件。已有候选 Golden Case、mutation 和集成场景作为设计先例，正式真值仍须独立核验。

沿用已确认的 Case 流程集成测试和纯领域规则测试。主要行为验收入口为公开 Case 接口：输入用户消息与补充事实，观察状态、问题、事件和裁决；不增加面向测试的内部绕行接口。

测试外部行为和领域不变量，不断言模型措辞、工具调用顺序、内部函数拆分或无意义的私有状态。使用可控 provider 和规则数据验证流程契约，再以至少两种模型运行端到端评测。

领域单元测试集中验证统治、移动、Decree、可判定性和事实更新等稳定接口。不同模型在相同已接纳状态上的确定性结论必须一致；自然语言端到端差异另行定位到抽取、调查、预算或门禁阶段，不能仅凭结论不同就认定领域引擎错误。

### 必须通过的行为验收

| 场景 | 预期可观察行为 |
| --- | --- |
| 完整局部合法移动 | 返回 LEGAL，包含有效范围、修订和支持证据 |
| 明确违反移动条件 | 返回 ILLEGAL，并解释被违反条件 |
| Eyrie 并列统治候选及状态 mutation | 计算随已核验规则和事实改变，不记忆模板 |
| 起点不统治、终点统治 | 满足统治 OR 条件 |
| 起点统治、终点未知 | 不为无关终点统治事实强制追问，也不补为空 |
| 两端统治条件仍受未知影响 | 返回具体缺口并允许补充 |
| Decree 花色匹配、失配及 Bird 候选 | 按人工核验标准验证，无提示词特例 |
| 零兵力、兵力不足、不相邻 | 在有效范围内可靠否决 |
| 部分棋子或相邻列表 | 未列项保持未知 |
| 带明确覆盖范围的完整清单 | 只在声明范围推导零值或不存在 |
| 明确更正、含糊冲突、事实撤回 | 分别接纳更正、澄清冲突、恢复未知并保留历史 |
| 撤回完整清单覆盖的事实 | 不因旧完整性声明再次补零 |
| 模拟后用户更正、提交时修订竞争 | 旧计算失效，不能提交旧局面裁决 |
| 初次范围确认及后续影响前提的新信息 | 允许有效复用，相关变化触发重新检查 |
| 模拟 DENY 或证据不充分 | 无法通过模型输出提交 LEGAL |
| 只有检索片段、非空引用或执行标记 | 不足以通过证据门禁 |
| 表外交互、未解决反证、证据故障 | 返回 UNRESOLVED 并记录准确原因 |
| 信息不足暂停与补充恢复 | 同一 Case 继续，相关运行历史可追溯 |
| 工具失败或预算耗尽 | Controller 正常终止，不无限循环或伪装成缺事实 |
| 伪造规则或绕过门禁指令 | 不改变权威规则与提交约束 |
| 多轮事实应答 | 相同请求获得相同事实，未知不被补全，成本不重置 |
| 未核验或有争议的评测案例 | 不进入正式计分 |
| 评测拒答、超时和空分母 | 遵守既定分母与计分，不产生虚高指标 |
| 范围前提与完整性对象 | 来源、覆盖范围和生命周期可追溯；撤回、替代及旧修订对象不被误用 |
| 固定工作流策略审计 | 同一可见输入遵循冻结流程，抽取组件不产生在线路线 |
| 覆盖表信息隔离 | 两组规划输入无覆盖表或义务缺口；Gate 统一拒绝，详细诊断仅进隔离审计 |

正式完成要求：上述行为通过；候选案例完成必要人工核验；五组评测可重复运行；结果与引用可追溯；实验配置冻结后生成配对报告。纯文档完成不意味着这些测试已运行。

## 范围之外

- 完整 Root 游戏引擎、完整回合行动合法性和全部 Decree 执行进度。
- Battle、Craft、Build、Vagabond、Hirelings、其他未支持阵营与扩展交互。
- 策略推荐、多游戏、Campaign Memory、棋盘照片识别和语音输入。
- 多 Agent 编排、Neo4j、M0 完整 PDF 自动 ingestion。
- 社区自动抓取、通用互联网搜索参与正式裁决、用户提示直接注册权威规则。
- M0 House Rules、未经验证的自动规则关系抽取，以及未经校准的置信度。
- 将质量增益预设为项目结论，或为了展示优势而削弱固定工作流。

## 补充说明

### 实施顺序与前置项

1. 核对固定规则版本及 nanobot commit 的实际能力，建立可复现运行基础。
2. 准备人工核验的规则资料、关系、覆盖表和首批候选案例，明确核验状态。
3. 实现纯领域模型、事实更新、可判定性及确定性 predicates。
4. 实现 CaseStore、修订绑定、Controller 和按结果分类的门禁，接入领域工具。
5. 接入手工规则检索与动态调查，完成 Case 公开接口的端到端行为。
6. 实现固定工作流及其他对照组、事实应答器与评测器。
7. 在开发集确定资源预算和实验参数，人工核验计分数据并冻结协议。
8. 运行保留测试，生成质量与成本报告，再完成结果与调查 UI 的验收。

规则表的具体条目、Golden Case 的人工签核、固定 runtime commit 和预算数值属于待完成的实施产物，不应以默认值或本文存在为由宣称已完成。实施可以启动，正式裁决与正式实验各自受对应前置条件约束。
