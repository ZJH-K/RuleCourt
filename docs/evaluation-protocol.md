# M0 评测协议

本协议记录已确认的实验设计。质量优先，核心比较为动态 Agent 与固定工作流；LLM-only、Vanilla RAG、Hybrid RAG + Reranker 用于观察整套系统的收益。预算数值和通过阈值在开发集试跑后、保留测试前锁定。

## 标准答案与独立核验

每个 Golden Case 至少包含：

- case ID、canonical family ID、类别、固定规则版本与裁决范围；
- 初始用户描述、已提供事实及来源、未知字段、清单完整性与适用前提；
- 首次结果标签、允许补充的事实，以及补充后的可判定性和终局标签；
- 必要规则、适用例外、判定依据和可接受的追问目标；
- 人工核验人、核验记录和 `draft / verified / disputed` 状态。

AI 可以准备初稿，正式计分前须由熟悉 Root 的人依据固定版本规则核验。被测领域引擎可辅助检查，但不能作为标准答案的唯一来源。存在争议的案例隔离为 disputed，不进入正式计分；隔离原因和数量仍须报告。本文档中的演示案例不自动成为 verified 数据。

核验后的保留测试标签和隐藏事实仅供评测器使用，不进入被测系统的上下文、规则覆盖表或工具返回。规则覆盖表仅描述通用验证义务，不包含案例答案或调查路线；两组调查策略均不直接读取该表。

## 数据划分

同一 canonical case 的改写与 mutation 进入同一 family，并整体分配到开发集或保留测试集。试跑、提示调整、规则实现修复和预算估算使用开发集。

保留测试结果不得用于事后修改本次成功标准或挑选有利案例。发现数据或实现错误时保留失败记录；修复后作为新的实验版本报告，不覆盖原结果。

## 首次结果与完整调查

每组均报告两种视角：

1. **首次结果**：在收到任何评测器补充事实之前给出的结果；正确提出信息不足也按首次标签评估。
2. **完整调查**：允许在统一预算内追问，直至确定裁决、无法解决、无可补充事实或预算耗尽。

完整调查跨越同一案例中的澄清恢复，不因产生新的 run ID 而重置评测预算。成本、工具调用和系统处理时延累计到调查结束；人工等待时间不混入系统时延。

### 事实应答器

使用预先标注的事实表，按问题目标返回事实，不使用自由生成的 LLM 用户来决定事实内容。

- 同一事实请求在所有组中得到同一答案，仅回答明确问到的内容。
- 无法补充的字段保持未知；不能根据标准标签反推或泄露事实。
- 支持按声明范围返回完整清单，但不把针对单项的提问扩展成完整局面。
- 重复询问仍消耗预算；含糊或无法映射的问题按统一规则要求明确目标。
- 记录追问轮次和所请求的事实范围，避免把“一次问全部”误解为更高质量的调查。

固定工作流按确定性依赖追问，Agent 动态选择目标；其他组采用各自的追问策略，但使用同一事实应答器和追问上限。问题目标映射协议在开发集确定后冻结。

## 对照公平性

固定工作流与 RuleCourt 共享状态抽取器、模型配置、规则库、领域引擎、规则覆盖表和提交门禁。固定工作流可以全量检查 M0 规则，不能故意削弱其规则访问、缺信息处理或证据验证。

两者采用相同的案例初始信息、可补充事实及预算上限。动态调查步骤和查询目标选择是主要变量；记录实际资源使用，不强制消耗相同数量的 token。检索索引、缓存条件、提示版本、代码版本、模型版本和运行参数一并保存。

LLM-only 和 RAG 组不凭空获得领域引擎能力，其结果由同一离线评测器评分；不能将整套系统相对它们的优势直接归因于动态 Agent。

### 实验处理变量：仅改变调查策略

实验处理变量是“如何选择下一步调查动作及参数”，不包括状态真值、领域能力、验证标准或额外信息权限。

| 维度 | Dynamic Agent | Fixed Workflow |
| --- | --- | --- |
| 动作选择 | LLM 根据当前可见历史在线选择 | 冻结的流程、分支条件和顺序确定性选择 |
| 查询与追问目标 | LLM 在线生成或选择 | 冻结模板、遍历规则和 Resolver 结果确定性生成 |
| 根据结果分支 | 允许在线改变调查路线 | 允许预定义的数据驱动分支，不要求线性固定步骤 |
| LLM 使用 | 共享抽取/解释能力，加上在线调查规划 | 仅共享抽取/解释能力，不输出路线、下一工具或查询策略 |
| 规则获取 | 同一规则原文、索引、关系和工具权限 | 同等访问，可全量读取规则 |
| 最终裁决 | 共享 Controller、领域引擎和验证器生成 | 同左 |
| 资源 | 同等预算上限，记录全部实际消耗 | 同左，不人为补齐不存在的规划消耗 |

两组使用相同抽取契约、提示及模型配置；共同的工具响应投影包含相同的事实、reason codes、公开规则关系、Resolver 缺失字段及领域 Decision。显式用户事实及这些领域结果不是覆盖表的隐藏调查路线，不为制造优势而屏蔽。

固定工作流实现与模板独立审阅、在开发集冻结；可人工利用正式规则设计流程，但不能从覆盖表在线或离线生成路线，也不能使用保留案例或隐藏标签优化流程。共享抽取组件不能返回规划指令，解释组件不能反向驱动调查。两组策略版本分别记录；规划调用计入 Agent 的 token、时延与成本。

该比较检验“LLM 在线调查策略”相对于已冻结确定性策略的增量，不宣称排除了全部计算量差异。固定工作流可凭全量规则和确定性分支达到同样结果。

### 验证信息隔离

规则覆盖表属于验证器私有输入。它可指定义务的适用条件、可接受证据和满足判据，不存储查询文本、工具顺序、next step 或推荐调查路径。

两组规划输入、会话、检索索引及工具返回均不得包含覆盖表内容、未满足义务列表、缺失规则 ID、最近通过的路线或 Gate 生成的查询建议。Gate 拒绝只返回统一的 VERIFICATION_NOT_SATISFIED；参数无效、状态修订过期及预算状态仍可以按共享接口报告。重复提交仍消耗预算，不能用变化的细分失败原因逐项枚举义务。

详细失败原因保存到隔离的审计记录，供运行结束后的核验与离线分析；不在同一次调查中反馈给任一策略。已通过裁决所用的证据仍按产品契约展示。公开规则及其关系、Resolver 与 simulator 的正常结果可被双方同等观察，但这些结果不能读取覆盖表来附加“下一步该查什么”。

正式运行前检查两组实际可见输入和工具响应，验证相同权限下仅策略不同；发现验证路线泄露的实验不纳入主比较，修复后以新配置版本重跑。

## 指标定义

各视角使用在该视角信息条件下独立标注的真值：首次视角仅考虑初始可用事实；完整调查视角考虑预先允许补充的事实。可判定性不随被测系统有没有问到事实而变化。

令 D 为该视角下有足够可用事实、在支持范围内能给出 LEGAL/ILLEGAL 的案例集合，A 为应返回信息不足或无法解决的案例集合。

| 指标 | 定义 |
| --- | --- |
| Correct Ruling Rate（主指标） | D 中正确给出 LEGAL/ILLEGAL 的案例数 / D 的案例数 |
| 裁决覆盖率 | D 中给出 LEGAL/ILLEGAL 的案例数 / D 的案例数 |
| 已裁决准确率 | 全体案例中正确的 LEGAL/ILLEGAL 数 / 全体案例中给出的 LEGAL/ILLEGAL 数；对 A 强行裁决计错 |
| 错误放行率 | 真值为 ILLEGAL 却输出 LEGAL 的案例数 / 真值为 ILLEGAL 的案例数 |
| 正确拒答率 | A 中拒答状态及原因类别符合标注的案例数 / A 的案例数 |

分母为零时报告 N/A 及样本数，不能填成 100%。D 上的错误、超时、拒答均不计为正确裁决。由于系统故障返回 UNRESOLVED，不能仅因状态与某例的标签相同而算作正确拒答。

首次结果另外报告四状态标签匹配，覆盖正确追问行为；完整调查 Correct Ruling Rate 是判断质量增益的主指标。两种视角分别列出集合与样本数，不能混用分母。

辅助报告必要证据支持情况、事实抽取与无依据推断、工具调用、token/成本、追问轮次、P50/P95 系统时延和失败原因。按类别列出配对结果及总体结果，重复运行和同 family 样本不能当作完全独立样本夸大结论。

## 预算、阈值与结论

开发集试跑后，在保留测试前冻结以下内容：

- 数据划分与已核验数据版本；
- 规则、规则覆盖表、各组实现、提示和模型配置；
- 时间、迭代、工具调用、成本及追问上限；
- 重复运行次数、随机性控制和配对统计方法；
- 最小质量增益阈值、错误放行不增加的判定标准，以及效率比较口径。

冻结项必须填写实际值，未填完不得声称正式实验已就绪。数值由开发集和资源条件确定，不在尚无试跑数据时伪造阈值。

质量增益要求完整调查主指标达到预先设定标准，且错误放行不增加。质量相当但成本、耗时或追问改善时，只报告效率增益。样本或证据不足时报告结论不充分；未达标准时报告“M0 尚未证明 Agent 增量价值”。完成实验与证明假设成立是两件不同的事。
